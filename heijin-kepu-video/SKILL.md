# 黑金科普动画视频

把一个话题做成 1920×1080、30fps、约 60–120 秒的科普动画：近黑背景 + 奶油白线条 + 金色强调，图表、数字、示意图一笔一笔「画」出来，底部是逐句字幕，全程只有一首背景音乐、没有配音。背景音乐是技能目录里的 `template/public/music.mp3`（开源仓库不附带，由分享这个技能的人另外提供，用户自己放进去）。

成品示例的风格：左上角年份/地点、右上角文献出处和红色小印章、居中的点阵/折线图/剪影示意图、粒子聚成的金色大字、底部宋体字幕里关键词标金。

**用户通常是零基础，不会看代码。** 你要自己完成全部步骤，只在最后交付成片；中途不要让用户去改文件、敲命令。遇到需要安装软件时，告诉用户你要装什么，再自己装。

## 工作流程

按顺序做，每一步做完再进入下一步。

### 第 1 步：确认话题

从用户的话里取出：话题、目标时长（默认 90 秒）、受众（默认普通大众）、有没有指定的观点或资料。只有话题完全缺失时才问用户，其他都用默认值。

### 第 2 步：准备环境

1. 运行 `node -v`。需要 18 或以上（推荐 20/22 LTS）。
   - 没有 Node：Windows 用 `winget install OpenJS.NodeJS.LTS`；macOS 有 Homebrew 用 `brew install node`，否则从 https://npmmirror.com/mirrors/node/ 下载 LTS 安装包。装完重新打开终端再检查。
2. 选一个工作目录：优先 `桌面/黑金科普/<话题>`（云端沙箱里就用当前工作目录下的 `黑金科普/<话题>`）。
3. 把本技能的 `template/` 文件夹**整个复制**到工作目录（不要在技能目录里直接改）。
4. 在工作目录里运行 `npm install`（`.npmrc` 已经配好国内镜像，约 1–3 分钟）。
5. 检查工作目录里有没有 `public/music.mp3`。没有的话：用户在对话里发了音乐文件，就把它复制成 `public/music.mp3`；否则照常做，交付时提醒用户「没有背景音乐，把 BGM 改名为 music.mp3 放到技能的 template/public/ 文件夹里，以后每条都会自动带上」。
6. 渲染要用浏览器内核：脚本会自动找电脑上的 Chrome / Edge（Windows 都自带 Edge）。都找不到时 Remotion 会尝试下载，国内网络可能失败——这时让用户装一个 Chrome 或 Edge，或设置环境变量 `BROWSER_PATH` 指向浏览器程序。

### 第 3 步：写文案（字幕）

先读 `references/writing.md`，按里面的结构写。要点：

- 5–9 场，每场 2–4 句字幕，每句尽量 ≤ 24 个字，最多 30 个字。总字数 ≈ 目标秒数 × 3.5。
- 开头 2 句内抛出反常识的问题或画面；中间用**具体的数字、年份、实验、人物**推进；后面有一次「反转」或「真正的原因」；结尾一句收束，点题。
- 关键词用 `【】` 标金色，反面/错误/危险用 `〖〗` 标红。每句最多标一处。
- 事实必须可靠：数字、年份、研究出处都要有来源（能联网就搜索核实）。不确定的说法换成确定的，或者不写。图表是示意时，画面上用 `Tag` 标「示意」。

### 第 4 步：设计分镜

读 `references/style.md`（视觉规范）和 `references/components.md`（现成组件）。给每一场定下：背景类型、画面主体、每句字幕出现时画面要发生的变化。优先用现成组件，组件没有的东西（剪影、地图、物体）用 SVG 自己画，参考 `references/scene-patterns.md`。

先在工作目录写一个 `分镜.md`（每场：字幕 + 画面描述），方便最后给用户看。

### 第 5 步：写代码

1. 改 `src/story.ts`：`META`（标题、封面文字、封面用哪一场）和 `SCENES`（每场的字幕、背景、组件）。
2. 删掉 `src/scenes/` 里的示例场景（`Scene1–5.tsx`、`iceberg.ts`），按新分镜写 `Scene1.tsx`、`Scene2.tsx`……每场一个文件，结构照 `references/components.md` 里的「场景模板」。
3. 动画时间一律用 `useScene()` 返回的 `cue(k)`（第 k 句字幕出现的帧）加偏移，**不要写死绝对帧数**——字幕时长会随文案变，写死就对不上。
4. 字幕、背景、换场、背景音乐、片尾、封面都已在框架里处理好，场景里**不要**再画字幕、背景，不要加 `<Audio>`。
5. 画面内容不要进入底部 140px（y > 940），那里是字幕区。

### 第 6 步：自检（必须做）

运行 `npm run check`：先做类型检查，再把每场截两张图到 `out/check/`。

- 报错就按报错改，直到通过。
- **逐张打开截图看**：有没有文字重叠、出界、压到字幕、某场画面空荡、颜色跑出黑金体系、字太小（正文 < 22px 看不清）。有问题就改代码再跑一次。
- 命令输出里的 `⚠` 警告（字幕太长等）也要处理。

`npm run gallery` 可以截出所有组件的样张（`out/check/gallery-*.jpg`），不确定组件长什么样时先看它。

### 第 7 步：渲染与交付

运行 `npm run render`（1 分钟的视频约需 1–5 分钟，取决于电脑）。完成后 `out/` 里有：

- `<标题>.mp4` — 成片（已做响度标准化）
- `封面_横_4比3.png`、`封面_竖_3比4.png`

交付时告诉用户：成片和封面的完整路径、时长、分镜.md 的位置，以及「想改哪句话或哪个画面，直接告诉我」。如果是在云端沙箱里，把三个文件作为附件/下载链接给用户。

## 修改请求

用户要改文案、换颜色、加一场、去掉片尾时：改 `story.ts` 或对应场景文件 → `npm run check` 看截图 → `npm run render`。片尾署名由 `META.credits` / `META.creditsText` 控制。

## 出问题时

看 `references/troubleshooting.md`。常见：npm 装不上（检查 `.npmrc` 镜像）、找不到浏览器、渲染时某帧超时（多半是场景里写了死循环或超大数组）。

## 不要做

- 不要换成别的背景音乐、不要加配音或音效（这是本技能的固定设定）；不要从网上下载音乐。
- 不要改成竖屏或改分辨率，除非用户明确要求。
- 不要用网络图片、视频素材、外链字体——全部画面用代码画，保证国内网络能渲染。
- 不要编造数据和文献出处。
